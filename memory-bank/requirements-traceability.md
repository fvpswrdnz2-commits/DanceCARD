## V2 验收标准追踪

| 状态 | 编号 | V2 验收标准 | 预期测试类型 | 预期验证重点 |
| --- | --- | --- | --- | --- |
| [ ] | AC-01 | 游客可以完整走通“城市 → 舞室 → 次卡 → 联系卖家”，过程中不存在行政区选择层级。 | 组件测试、端到端测试 | 点击城市直接进入该城市的舞室列表；完成未登录浏览和联系路径。 |
| [x] | AC-02 | 同一舞室的次卡默认按单节价格从低到高展示。 | 单元测试、组件测试、端到端测试 | 验证排序规则；同价记录按发布时间从新到旧保持稳定顺序。 |
| [x] | AC-03 | 游客无需登录即可浏览和复制卖家微信号。 | 组件测试、端到端测试 | 验证游客可浏览，并可直接复制单条有效次卡的微信号。 |
| [x] | AC-04 | 未登录用户点击“添加次卡”会进入登录流程，并能在登录后返回原舞室继续发布。 | 组件测试、端到端测试 | 验证登录拦截、原舞室上下文保存和登录后返回路径。 |
| [x] | AC-05 | 登录用户能成功发布包含全部必填字段的次卡。 | 单元测试、组件测试、端到端测试 | 验证必填字段校验及有效表单发布成功。 |
| [x] | AC-06 | 次卡只能绑定发布入口对应的舞室。 | 单元测试、端到端测试 | 验证舞室只读绑定，且客户端或请求篡改不能改变归属。 |
| [x] | AC-07 | 登录用户只能管理自己发布的次卡。 | 单元测试、端到端测试 | 以两个用户验证本人操作成功、跨用户操作失败。 |
| [x] | AC-08 | 卖家可以编辑、隐藏、恢复或删除自己的次卡。 | 组件测试、端到端测试 | 验证四类操作及其对公开列表和“我的次卡”的影响。 |
| [x] | AC-09 | 已过期次卡不出现在公开列表，但仍可在卖家的“我的次卡”中查看。 | 单元测试、组件测试、端到端测试 | 按 `Asia/Shanghai` 验证过期公开条件与卖家私有可见性。 |
| [ ] | AC-10 | 管理员可以维护城市和城市级舞室，并处理违规次卡。 | 组件测试、数据库测试、端到端测试 | 验证同城舞室去重、通用分店信息、停用可见性与普通用户拒绝访问。 |
| [x] | AC-11 | 常见问题、发布流程和次卡详情中能看到相应的风险说明。 | 组件测试、端到端测试 | 分别检查三个规定位置及其风险说明。 |
| [x] | AC-12 | 产品中不存在支付、购买记录、已售出、收藏、举报、定位或在线聊天功能。 | 组件测试、端到端测试 | 检查用户端、管理端可见界面和完整 V2 旅程中不存在所列功能入口。 |

## 实际验证证据

- AC-01：V2 组件和 Playwright 旅程待验证城市直接进入舞室，且不再出现行政区页面。
- AC-02–03、11–12：Playwright 游客旅程、直接复制联系方式、详情风险说明、FAQ 和范围扫描。
- AC-04：Playwright 验证未登录跳转与原舞室返回路径，并由返回路径单元测试覆盖恶意输入。
- AC-05–08：部署环境中完整走通发布、编辑、隐藏、恢复和软删除；数据库测试覆盖伪造归属与跨用户操作。
- AC-09：数据库过期可见性测试通过，部署环境的“我的次卡”正确显示已过期状态。
- AC-10：V2 管理后台组件、城市级舞室迁移和事务性数据库权限测试待执行；部署后再补充真实环境证据。

本表只证明开发环境中的产品核心闭环。它不代表正式生产发布；生产环境、域名、隐私政策、用户协议和专业法律审阅仍未完成。
