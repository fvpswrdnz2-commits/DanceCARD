# DanceCARD 产品设计文档

- 文档版本：V1.0
- 产品形态：V1 正式发布移动端 H5；微信端仅保证可构建并通过开发者工具冒烟测试
- 文档状态：需求确认版

## 1. 产品概述

### 1.1 产品定位

DanceCARD 是一个面向舞蹈爱好者的闲置舞蹈次卡信息交换工具，连接希望转让剩余课程的卖家，以及希望以较低成本、较少课时体验舞室的买家。

平台只负责组织和展示信息，并帮助买卖双方取得联系。双方通过微信自行沟通并在线下完成交易。

平台不参与支付、资金托管、交易担保、课程核销或纠纷处理，也不验证用户、次卡或交易信息的真实性。

### 1.2 核心价值

- 为卖家提供面向舞蹈爱好者的垂直发布渠道，减少闲置课程浪费。
- 为买家降低寻找少量、低价舞蹈课程的信息检索成本。
- 按城市、行政区域和舞室组织信息，帮助有明确消费目标的用户快速找到次卡。

### 1.3 目标用户

产品主要服务已有明确需求、对舞室或舞蹈消费有一定了解的舞蹈爱好者，不以零基础教学、舞室发现或泛内容浏览为核心场景。

典型场景包括：

- 买了过多课程，无法在有效期内使用完。
- 因搬家、出差或工作变化无法继续上课。
- 在某个城市短期停留，希望购买少量课程。
- 想体验特定舞室，但不愿一次购买大额课包。

## 2. 产品目标与边界

### 2.1 V1 目标

V1 需要跑通两条核心路径：

1. 买家按城市、行政区域和舞室找到次卡，并复制卖家微信号。
2. 卖家登录后，在指定舞室下发布和管理自己的次卡。

### 2.2 V1 包含

- 正式发布移动端 H5。
- 微信小程序代码保持可构建，并在微信开发者工具中完成冒烟测试。
- 城市、行政区域和舞室的分级浏览。
- 舞室下的次卡列表及详情。
- 卖家登录与次卡发布。
- 我的次卡：查看、编辑、隐藏、恢复展示和删除。
- 点击联系卖家后直接复制微信号。
- 常见问题与免责声明。
- 城市、区域、舞室、次卡及用户的基础管理后台。
- 到期次卡自动停止公开展示。

### 2.3 V1 不包含

- 微信登录、微信小程序提交审核、发布和真机验收。
- 平台支付、抽佣或资金托管。
- 交易担保、真实性认证或纠纷处理。
- 站内聊天、课程核销或购买记录。
- 收藏、举报、评价、信用体系或已售出状态。
- 图片上传。
- 定位、附近舞室、地图或距离排序。
- 舞室介绍、评分、老师介绍、课程表等点评型内容。
- 推荐流、社区内容或个性化推荐。
- 用户直接创建舞室。

## 3. 产品设计原则

### 3.1 信息工具，而非交易平台

产品只连接双方，不介入交易过程。界面和文案不得暗示平台为交易结果提供保证。

### 3.2 目标导向，而非内容发现

用户通过“城市 → 行政区域 → 舞室 → 次卡”逐级检索，不设置推荐信息流或“附近”功能。

### 3.3 信息精简且可比较

列表只展示影响快速决策的关键信息，并在同一舞室内默认按单节价格从低到高排序。

### 3.4 发布必须绑定舞室

次卡只能从具体舞室页面发起发布，并自动绑定该舞室。不得发布未归属具体舞室的泛课程信息。

### 3.5 用户自行维护信息状态

平台不判断次卡是否成交，也不设置“已售出”。卖家通过隐藏或删除管理不再有效的信息；系统仅对已过期信息自动停止展示。

## 4. 用户角色与权限

### 4.1 游客 / 买家

无需登录，可以：

- 浏览城市、区域和舞室。
- 查看次卡列表和详情。
- 点击卖家昵称并复制微信号。
- 阅读常见问题和免责声明。

不能：

- 发布或管理次卡。
- 访问管理后台。

### 4.2 登录用户 / 卖家

除游客权限外，可以：

- 在具体舞室页面发布次卡。
- 查看自己发布的全部次卡。
- 编辑、隐藏、恢复展示或删除自己的次卡。
- 不受发布数量限制，可跨城市、区域和舞室发布。

### 4.3 管理员

可以：

- 管理城市及行政区域。
- 添加、修改和停用舞室。
- 人工核对舞室是否重复。
- 查看、隐藏或删除违规次卡。
- 查看并管理必要的用户信息。

## 6. 核心用户流程

### 6.1 买家流程

```text
打开产品
→ 进入“次卡”
→ 选择城市
→ 选择行政区域
→ 选择舞室
→ 按单节价格浏览次卡
→ 查看次卡详情
→ 点击卖家昵称
→ 复制微信号
→ 双方自行沟通和交易
```

### 6.2 卖家发布流程

```text
打开产品
→ 进入“次卡”
→ 选择城市
→ 选择行政区域
→ 选择舞室
→ 点击“添加次卡”
→ 未登录时先完成登录
→ 填写必填信息
→ 阅读免责声明
→ 发布
→ 次卡进入该舞室列表
```

### 6.3 卖家管理流程

```text
进入“我的次卡”
→ 未登录时先完成登录
→ 查看自己发布的次卡
→ 编辑、隐藏、恢复展示或删除
```

### 6.4 新增舞室流程

```text
用户未找到目标舞室
→ 按常见问题中的说明联系管理员
→ 提供舞室名称、城市及大众点评或地图截图等信息
→ 管理员检查系统中是否已存在
→ 不存在时由管理员手动添加
```

用户不能在前台直接创建舞室。

## 7. 页面设计与功能规格

### 7.1 次卡：首页 / 城市选择

页面目标：让用户选择目标城市。

页面内容：

- 页面标题或产品名称。
- 已开放城市列表。
- 底部一级导航。

交互规则：

- 点击城市进入对应行政区域选择页。
- 不申请定位，不展示“附近”。
- 暂无数据的城市可不展示，或由后台配置为停用。

### 7.2 行政区域选择页

页面目标：缩小目标舞室范围。

页面内容：

- 当前城市名称。
- 该城市下已启用的行政区域列表。

交互规则：

- 点击行政区域进入舞室列表页。
- 区域只按行政区划分，不使用商圈。

### 7.3 舞室列表页

页面目标：帮助用户找到明确目标舞室。

页面内容：

- 当前城市和行政区域。
- 舞室名称列表。
- 找不到舞室时通过弹窗展示新增说明，引导用户发送邮件至 `m18800126467@163.com`，并提交舞室名称、城市、行政区及大众点评或地图截图。

不展示舞室图片、简介、评分、老师、课程表或距离。

### 7.4 舞室次卡页

页面目标：展示指定舞室当前有效且公开的次卡。

页面结构：

1. 舞室名称。
2. “添加次卡”按钮。
3. 次卡列表。

列表单项展示：

- 卖家昵称。
- 可出售的剩余课时，例如“分享 10 个次卡”。
- 单节价格，例如“¥60/次”。
- 发布时间。

交互规则：

- 默认按单节价格升序排列；价格相同时可按发布时间倒序作为稳定排序规则。
- 只展示状态为公开且尚未到期的次卡。
- 点击联系操作后直接复制微信号，不增加二次确认弹窗。
- 点击列表项其他区域进入次卡详情页。
- 点击“添加次卡”时，如未登录则先进入登录流程；登录后返回当前舞室的发布页。

空状态：

- 提示“这个舞室暂时还没有可用次卡”。
- 保留“添加次卡”按钮。

### 7.5 次卡详情页

页面目标：展示完整信息，并让买家联系卖家。

展示字段：

- 舞室名称。
- 卖家昵称。
- 剩余课时。
- 单节价格。
- 使用截止日期。
- 可用舞种。
- 使用限制。
- 备注。
- 发布时间。

主要操作：

- 点击卖家昵称或“联系卖家”，直接复制微信号。

免责声明：

> 平台无法验证任何用户及次卡信息的真实性和可靠性。诈骗有可能发生，请谨慎使用。平台不参与双方交易，也不对基于本平台发生的任何交易及其结果承担责任。

### 7.6 添加次卡页

入口：仅从具体舞室次卡页进入，舞室由系统自动绑定且不可自由填写。

必填字段：

| 字段 | 规则 |
| --- | --- |
| 舞室 | 由入口自动绑定，只读 |
| 卖家昵称 | 用于公开展示 |
| 微信号 | 不直接公开展示，用于复制联系 |
| 剩余课时 | 正整数 |
| 单节价格 | 大于 0，单位为人民币元 |
| 使用截止日期 | 不得早于当前日期 |
| 可用舞种 | 选择“全部舞种”或一个/多个指定舞种 |

选填字段：

| 字段 | 说明 |
| --- | --- |
| 使用限制 | 如仅限工作日、指定老师、不可用于大师课等 |
| 备注 | 其他需要买家了解的信息 |

字段限制：

- 时区统一使用 `Asia/Shanghai`。
- 截止日期当天 23:59:59 前有效。
- 单节价格使用人民币，最多两位小数且必须大于 0。
- 剩余课时范围为 1–999。
- 卖家昵称长度为 1–30 字符。
- 微信号长度为 1–50 字符。
- 使用限制最多 200 字符。
- 备注最多 500 字符。
- 账号保存默认昵称和默认微信号；发布时自动填入，卖家可针对当前次卡修改。
- 已发布次卡保存发布时的昵称和微信号快照，后续修改账号默认值不影响历史次卡。

舞种规则：

- 通用卡选择“全部舞种”。
- 专项卡选择一个或多个指定舞种。
- 预设舞种可包含 Hip-hop、Jazz、Locking、Popping、House、Waacking、K-pop 等，并提供“其他”。
- 选择“其他”后必须填写自定义舞种名称。
- “全部舞种”与指定舞种互斥。

发布规则：

- 不填写原价。
- 不设置最少购买节数或拆售规则；具体购买数量由双方自行沟通。
- 发布前展示免责声明；提交发布即表示发布者已知晓平台边界。
- 发布成功后返回当前舞室次卡页，并展示新发布信息。

### 7.7 登录页

V1 H5 使用手机号与短信验证码登录。手机号首次验证成功时自动创建普通用户账号，不设置密码。

规则：

- 浏览和联系卖家无需登录。
- 发布及管理次卡必须登录。
- 普通用户可以使用手机号验证码注册或登录。
- 管理员注册入口不对外开放；运营方指定手机号首次完成验证码登录后，由 CloudBase 控制台手动设置为首个管理员。该手机号只存在于受控运行环境，不写入公开代码仓库。
- V1 微信端不实现微信登录；后续迁移时保持业务用户 ID 与登录渠道解耦。

### 7.8 我的次卡

未登录状态：

- 显示登录引导。

登录状态：

- 展示当前用户发布的全部未删除次卡，包括公开、手动隐藏和已过期状态。
- 每条次卡显示舞室、剩余课时、单节价格、截止日期和当前状态。

支持操作：

- 编辑。
- 隐藏。
- 恢复展示；只有尚未过期的信息可以恢复。
- 删除；删除前二次确认。

不展示购买记录，也不提供“标记已售出”。卖家完成交易后可自行隐藏或删除。

### 7.9 常见问题

至少包含：

1. 舞卡是什么，平台提供什么服务？
2. 如何查找并联系卖家？
3. 如何发布和管理次卡？
4. 找不到城市、区域或舞室怎么办？
5. 平台是否参与支付或担保交易？
6. 使用时应注意哪些风险？
7. 完整免责声明。

新增城市、区域或舞室的联系邮箱：`m18800126467@163.com`。管理员手机号仅用于管理员身份登录，不作为前台新增舞室联系方式展示，也不得写入公开代码仓库。

## 9. 状态与自动规则

### 9.1 次卡状态

- 公开展示：卖家设为公开且未过期。
- 手动隐藏：卖家主动隐藏，可在到期前恢复。
- 已过期：截止日期早于当前日期，不再公开展示。
- 管理员隐藏：因违规等原因被管理员隐藏，普通用户不可自行恢复。
- 已删除：不再展示；实现上建议软删除以便审计和误操作恢复。
- 上级停用：城市、行政区域或舞室停用后，其下次卡全部停止公开，但不删除数据。
- 用户禁用：发布用户被禁用后，其次卡全部停止公开，但不删除数据。

产品不设置“已售出”状态。

### 9.2 过期处理

- 查询公开列表时必须实时排除过期记录，保证即使定时任务延迟也不会显示过期卡。
- 后台可使用每日定时任务将过期记录标记为隐藏原因 `expired`，便于管理和统计。
- 已过期记录继续出现在卖家的“我的次卡”中，但不能恢复公开；卖家可编辑截止日期后再恢复。
- 所有日期判断统一使用 `Asia/Shanghai`；截止日期当天 23:59:59 前仍视为有效。

### 9.3 排序规则

同一舞室公开次卡的默认排序：

1. 单节价格从低到高。
2. 价格相同时，发布时间从新到旧。

次卡列表每页 20 条，按相同排序规则分页加载。

## 10. 管理后台

### 10.1 城市与区域管理

- 新增、编辑、启用和停用城市。
- 在城市下新增、编辑、启用和停用行政区域。
- 配置展示顺序。

### 10.2 舞室管理

- 按城市和行政区域查询舞室。
- 添加、编辑、启用和停用舞室。
- 添加前人工检索是否存在名称相同或相似的舞室。
- 保存必要的核对信息。
- 舞室名称标准化后，阻止在同一行政区域内新增精确重复项。
- 相似名称只向管理员发出警告，由管理员人工决定是否添加。

用户申请新增舞室不需要独立的前台工单系统；V1 按常见问题中的联系方式联系管理员。

### 10.3 次卡内容管理

- 查看和检索全部次卡。
- 按用户、舞室、状态或日期筛选。
- 隐藏或软删除违规信息。
- 记录管理员操作原因。

### 10.4 用户管理

- 查看用户基本资料和发布记录。
- 禁用严重违规用户。
- 管理员不能代表用户确认交易或修改交易结果。
- 禁用用户后，其发布的次卡停止公开；恢复用户后，仅原本公开且仍有效的次卡可重新公开。

V1 必须交付独立的基础管理后台。CloudBase 控制台只用于首次设置管理员和紧急运维，不替代产品管理后台。

## 11. 隐私与风险提示

### 11.1 微信号保护

- 次卡列表和详情默认只展示昵称，不直接显示微信号文本。
- 用户主动点击联系操作后才复制微信号。
- 联系操作直接复制微信号，不增加二次确认弹窗；风险提示常驻在详情页联系操作附近。
- 后端只向必要的联系接口返回微信号，避免在无需使用时批量暴露。
- V1 不对游客复制微信号增加登录、验证码或频率限制。

### 11.2 免责声明位置

按照参考产品的轻量方式呈现：

- 次卡详情的联系卖家操作附近常驻展示风险提示。
- 发布页面提交前展示免责声明。
- 常见问题页面长期展示完整免责声明。

### 11.3 免责声明建议文本

> 本平台仅提供次卡信息展示及用户联系方式连接服务，无法验证任何用户、次卡或其他信息的真实性、准确性和可靠性。诈骗或其他交易风险可能发生，请用户谨慎核实并自行决定是否交易。平台不参与支付、担保、核销或纠纷处理，对用户基于本平台自行发生的沟通、交易及其后果不承担责任。

正式上线前，应根据实际运营主体和上线地区咨询专业人士，对隐私政策、用户协议及免责条款进行审阅。

## 12. 非功能要求

### 12.1 移动端优先

- V1 Web 页面以手机竖屏体验为主。
- 布局、导航和交互遵循小程序常见模式。
- 避免依赖仅浏览器可用且难以迁移到小程序的核心交互。

### 12.2 性能

- 城市、区域和舞室列表应快速加载。
- 次卡列表每页加载 20 条。
- 默认排序和公开条件应由数据查询层完成。

### 12.3 安全

- 只有登录用户可创建次卡。
- 用户只能编辑、隐藏或删除自己的次卡。
- 管理员权限与普通用户权限严格隔离。
- 微信号等联系方式不得出现在公开批量列表接口中。

### 12.4 可迁移性

- 产品状态、数据模型和业务规则不依赖 Web 页面实现。
- 用户身份与具体登录渠道解耦，为微信登录预留扩展能力。
- 后续微信小程序应复用同一业务数据和后端接口。

### 12.5 视觉方向

产品名称暂定为 `DanceCARD`。用户已确认的深色视觉参考保存在 `memory-bank/assets/ui-reference.png`；旧 Neo-pop 方案归档在 `memory-bank/assets/ui-reference-neo-pop-archive.png`，不再作为实现依据。

- 整体采用深色编辑感与赛事档案感：近黑背景、暖白正文、珊瑚橙主操作、暗金辅助信息和冷灰蓝分隔线。
- 使用细线框、小圆角或直角、紧凑编号、英文元数据标签和明确的信息层级，不使用大圆角气泡卡片、玻璃拟态或渐变。
- 价格和主要操作使用珊瑚橙；时间、位置和辅助状态可使用暗金；其余文字优先保证对比度和可读性。
- 标题使用粗重无衬线字体，品牌、数字和英文标签可使用紧缩字体感；中文正文保持清晰的系统无衬线字体。
- 城市页使用编号式城市列表和低对比度字母水印；其他页面沿用同一套线框、标签和按钮语言。
- 底部三个一级导航必须在所有用户端页面持续可见，使用细线容器、数字编号和珊瑚橙激活标记。
- 装饰几何图形只能低对比度使用，不得抢夺城市、舞室、价格和联系操作的视觉优先级。

## 13. V1 验收标准

满足以下条件即可认为核心 MVP 闭环完成：

1. 游客可以完整走通“城市 → 行政区域 → 舞室 → 次卡 → 联系卖家”。
2. 同一舞室的次卡默认按单节价格从低到高展示。
3. 游客无需登录即可浏览和复制卖家微信号。
4. 未登录用户点击“添加次卡”会进入登录流程，并能在登录后返回原舞室继续发布。
5. 登录用户能成功发布包含全部必填字段的次卡。
6. 次卡只能绑定发布入口对应的舞室。
7. 登录用户只能管理自己发布的次卡。
8. 卖家可以编辑、隐藏、恢复或删除自己的次卡。
9. 已过期次卡不出现在公开列表，但仍可在卖家的“我的次卡”中查看。
10. 管理员可以维护城市、区域和舞室，并处理违规次卡。
11. 常见问题、发布流程和次卡详情中能看到相应的风险说明。
12. 产品中不存在支付、购买记录、已售出、收藏、举报、定位或在线聊天功能。

## 14. 后续迭代方向（不属于 V1）

- 微信小程序与微信登录。
- 舞室新增申请的站内工单。
- 举报及基础信用机制。
- 新次卡提醒。
- 在需求验证后探索符合社区定位的可持续运营方式。

上述方向仅作为扩展可能，不应在 V1 开发中提前扩大范围。

## 15. 产品核心定义

> DanceCARD 是一个帮助舞蹈爱好者寻找和释放闲置舞课资源的信息交换工具。它降低信息检索和联系成本，但不参与或担保交易。
